# D-Cut adaptive verifier step-length — vLLM 0.22.x monkey-patch plugin

Port of **vLLM PR #44885** (`[Spec Decode] Adaptive verifier step-length for DFlash/PARD (D-Cut-style)`, closed & unmerged) as a self-contained plugin — **no vLLM source files are edited**.

Core algorithm follows AngelSlim D-Cut: hardware-profiled ITL cost table + draft-confidence prefix-product scores + batch-wide global top-K → each step the verifier only checks an adaptive subset of the DFlash draft block.

> ⚠️ **AI-assisted, untested on hardware.** This was generated by porting the upstream PR onto the 0.22.x runner by static analysis. Review every line and smoke-test on hardware before relying on it.

## Hard constraints

- **DFlash / PARD only.** Active only for `method=dflash`, or `method=draft_model` with `parallel_drafting=true`.
- **Disable async scheduling.** Run with `--no-async-scheduling`.
- **High-concurrency win, low-concurrency cost.** Low concurrency can regress because the controller adds D2H + CPU decision overhead.

## Check the pure controller algorithm

```bash
python3 - <<'PY'
from dcut.verify_adaptive_controller import choose_query_lens_discrete
r = choose_query_lens_discrete(
    probs=[[0.9, 0.8], [0.5, 0.5]],
    base_batch_size=2,
    q_levels=[2, 4, 6],
    cost_lookup=lambda q: {2: 1.0, 4: 1.2, 6: 2.0}[q],
    max_draft_len=2,
)
print(r)
assert r["draft_lens"] == [2, 0]
assert r["best_Q"] == 4
PY
```
